# Validation record

The repository is designed so controls can be reproduced locally and in GitHub
Actions. The latest commit's Actions run is the authoritative public record.

Validated locally before publication:

- Go formatting, unit tests and vet
- Python AI-triage unit tests
- negative and positive vulnerability gate paths
- remediation evidence verification
- Terraform formatting and validation without a backend
- Gitleaks source/history scan
- Docker build, non-root runtime and API smoke test
- Trivy filesystem, IaC and image gates
- SPDX and CycloneDX SBOM generation
- GitHub Actions syntax with actionlint

## Remediation exercised during validation

The first Trivy image scan failed closed on four High-severity Go standard
library findings in Go 1.25.14 (`CVE-2026-111943`, `CVE-2026-78667`,
`CVE-2026-78669`, and `CVE-2026-97031`). The build baseline was upgraded to
Go 1.27.3, the image was rebuilt, and the identical Trivy 0.74.0
High/Critical policy returned **0 findings**. No ignore rule or severity
downgrade was used.

The local API smoke test also confirmed the image runs as UID/GID `65532:65532`.
SPDX and CycloneDX documents generated by Syft 1.38.2 were parsed as valid JSON.

Environment-dependent controls:

- Cosign keyless signing and GitHub provenance require the tagged GitHub
  Actions identity and are validated by the release workflow.
- Terraform apply requires an intentionally selected Kubernetes context.
- The Jenkins reference requires a controller, compatible plugins and labelled
  tool-equipped agent; no public controller is claimed.
